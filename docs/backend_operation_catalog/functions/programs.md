| `onProgramGuestDirectoryGuestChanged` / `onProgramGuestDirectoryFunctionGuestChanged` / `onProgramGuestDirectoryHouseholdChanged` / `onProgramGuestDirectoryGroupChanged` | Firestore triggers on `programGuests`, `programFunctionGuests`, `programHouseholds` and `programGuestGroups` writes | Host guest list, guest desk, planner and programme inbox audience | `programGuestDirectoryViews/{kind}__{sourceId}` | Replace `listProgramGuests` for the Host app (#2306). One row per guest, household and group, exactly what the callable returned for a page: a guest's fields with its function rows (at most 60, in function id order), a household's label, members and revision, a group's label, dimension, order, member count and revision. Each row is re-evaluated in one transaction that rereads its source and, for a guest, the selected workspace field assertions and its function rows, and is written only on change. The trigger resolves the name, phone and email from the assertions as the callable does, so a guest whose name is not disclosable has no row and the assertions, field authority, household contact and consent never reach a row. A function row write re-evaluates its guest only when invitation, RSVP, attendance, party size or ownership moves; a row of another programme or organizer is skipped and logged. A source that fails its contract keeps the previous row. The programme owner and a guest relations duty from one assignment covering the whole programme (`programAccessViews.programAll`) read the rows under rules. |
